# High-Level Design (HLD): Платформа для стриминга фильмов (CinemaStream)

## 1. Обзор системы и Требования

### Функциональные требования (Что система делает)
* Пользователи могут регистрироваться, входить в систему и управлять профилем.
* Просмотр каталога фильмов с фильтрацией по жанрам, годам, рейтингам.
* Полнотекстовый поиск фильмов по названию, актерам, режиссерам.
* Воспроизведение видео (стриминг) с адаптивным качеством.
* Ведение списка «Мое» (избранное, история просмотров, продолжение просмотра).

### Нефункциональные требования (Как система работает)
* **Высокая доступность (High Availability):** Система должна работать 24/7, видео не должно «падать».
* **Низкая задержка (Low Latency):** Видео должно начинаться быстро (Time to First Frame < 2 сек), без долгих буферизаций.
* **Масштабируемость (Scalability):** Система должна автоматически масштабироваться при наплыве пользователей (например, при выходе нового хита).
* **Безопасность:** Защита видео от несанкционированного скачивания и встраивания на сторонние сайты.

## 2. Высокоуровневая Архитектура (Компоненты)

Система построена по **микросервисной архитектуре**, что позволяет масштабировать независимые части (например, сервис видео не зависит от сервиса пользователей).

### Основные блоки:
1. **Клиентская часть (Frontend / Web App):** SPA (React/Next.js). Отвечает за UI и интеграцию видеоплеера (например, `video.js` или `hls.js`).
2. **API Gateway / Load Balancer:** Единая точка входа. Маршрутизирует запросы, занимается rate-limiting, аутентификацией (проверка JWT) и агрегацией данных.
3. **Микросервисы (Backend):**
   * **User Service:** Управление пользователями, профилями, подписками и авторизацией.
   * **Catalog Service:** Управление метаданными фильмов (название, описание, жанры, постеры).
   * **Search Service:** Полнотекстовый поиск и фильтрация.
   * **Watch History / Recommendation Service:** Отслеживание прогресса просмотра, формирование персональных рекомендаций.
   * **Media/Streaming Service:** Отвечает за выдачу ссылок на видео, проверку прав доступа и генерацию временных подписанных URL.

## 3. Стратегия хранения данных (Polyglot Persistence)

Для разных задач используются специализированные базы данных:

* **PostgreSQL (Реляционная БД):** 
  * *Назначение:* Пользователи, транзакции, подписки, жесткие связи.
* **MongoDB или DynamoDB (NoSQL / Документная БД):**
  * *Назначение:* Каталог фильмов. Метаданные имеют гибкую структуру, NoSQL позволяет легко добавлять новые атрибуты без миграций.
* **Elasticsearch (Поисковый движок):**
  * *Назначение:* Быстрый поиск по фильмам, актерам, фильтрация с учетом опечаток (fuzzy search).
* **Redis (In-memory Cache):**
  * *Назначение:* Кэширование популярных данных (топ-100 фильмов, сессии пользователей, токены), чтобы снизить нагрузку на основные БД.
* **AWS S3 / Cloudflare R2 (Object Storage):**
  * *Назначение:* Хранение исходных видеофайлов, нарезанных чанков, постеров, аватарок.
* **CDN (Cloudflare / AWS CloudFront):**
  * *Назначение:* Раздача видеофайлов и статики пользователям из серверов, географически близких к ним. Критически важно для снижения задержек и нагрузки на origin-серверы.

## 4. Конвейер доставки видео (Video Delivery Pipeline)

### Процесс загрузки и обработки (Upload & Transcoding)
1. Администратор загружает "сырой" тяжелый видеофайл (например, 50 ГБ, 4K) в **Object Storage (S3)**.
2. S3 отправляет событие (Event) в **Message Queue** (Kafka/RabbitMQ).
3. **Transcoding Service** забирает задачу из очереди. С помощью FFmpeg или облачных сервисов (AWS MediaConvert) он:
   * Нарезает видео на маленькие кусочки (чанки) по 2-10 секунд.
   * Конвертирует в разные разрешения (360p, 720p, 1080p, 4K).
   * Формирует плейлист (`.m3u8` для HLS или `.mpd` для DASH).
4. Обработанные кусочки сохраняются обратно в **S3**.
5. **Catalog Service** обновляет базу данных, привязывая фильм к новым URL.

### Процесс просмотра (Playback)
1. Пользователь нажимает "Play" на фронте.
2. Фронтенд запрашивает у **Media Service** ссылку на видео (или манифест `.m3u8`).
3. **Media Service** проверяет права (активна ли подписка?) и генерирует **Signed URL** (временную защищенную ссылку на CDN/S3).
4. Фронтенд отдает эту ссылку видеоплееру.
5. Плеер через **CDN** начинает подгружать кусочки видео (чанки) и воспроизводить их, динамически меняя качество (ABR - Adaptive Bitrate Streaming).

## 5. Стек технологий (Рекомендации)

* **Frontend:** React.js / Next.js, TailwindCSS, `hls.js` или `video.js`.
* **Backend:** Node.js (NestJS) или Go (для высоконагруженных частей, например, Media Service), или Java (Spring Boot).
* **Базы данных:** PostgreSQL, MongoDB, Redis, Elasticsearch.
* **Инфраструктура:** AWS (S3, CloudFront, RDS, EKS), Docker, Kubernetes, Terraform.
* **Очереди и обработка:** Apache Kafka или RabbitMQ, FFmpeg / AWS MediaConvert.
